# Настройка собственной аналитики KinderCore

Система пока не активна: endpoint возвращает 503, пока не будет создан binding `ANALYTICS_DB`. Клиентский сбор событий намеренно ещё не включён.

## 1. Отдельная D1 база
1. Cloudflare Dashboard → Storage & databases → D1 SQL Database → Create.
2. Название, например `kindercore-site-analytics`.
3. Открой SQL Console и выполни содержимое `docs/analytics-schema.sql`.
4. Workers & Pages → проект `kinder-core-wabsite` → Settings → Functions → D1 database bindings (название раздела может отличаться) → Add binding.
5. Variable name: `ANALYTICS_DB`; выбери только что созданную базу.
6. Не подключать существующий KinderCRM/Supabase и не вставлять токены в репозиторий.

## 2. Ограничение злоупотреблений
Перед активацией добавить Cloudflare rate limiting для `/api/analytics` по доступным функциям аккаунта. Endpoint не хранит IP/User-Agent, поэтому не следует считать его защитой от автоматического спама сам по себе.

## 3. Проверка до включения клиентского сбора
- POST с корректным JSON и разрешённым событием после настройки D1 возвращает 202.
- GET возвращает 405; неправильный Content-Type — 415; неправильный JSON — 400; событие вне allowlist — 400; тело больше 2 KB — 413.
- Без binding endpoint возвращает 503 и ничего не записывает.
- Проверить таблицу: не должно быть IP, User-Agent, полного URL, query string, cookies или свободных текстовых полей.
- Сначала завершить юридическую проверку фактической обработки технических метаданных Cloudflare Pages, правового основания и срока хранения. До этого клиентский код не должен отправлять события.

## 4. Активация клиентского кода
После проверки endpoint и правовых условий добавить локальный модуль, который отправляет только `page_view` и фиксированные `cta_click` события на `/api/analytics`. Ошибки аналитики не должны ломать сайт. Не включать UTM-параметры до отдельного решения о допустимом allowlist и сроке хранения.
